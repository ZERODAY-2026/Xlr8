# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (locked by 01-CONTEXT.md D-04):** Phase 1 browser UI is the **upload shell + chunk list with page numbers only**. The Q&A screen, tier badges, escalation banner and disclaimer footer belong to Phase 2 and are NOT built this phase — the semantic tier colors below are token reservations only. Design direction: **Operate mode** (a working tool — scanability and consistency over expression). Visual anchor: upload drop zone (centered, largest contrast) pre-upload; document title + chunk count header post-upload, chunk rows below.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge inner padding |
| sm | 8px | Compact element spacing, chunk-row internal gaps |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, drop-zone padding |
| xl | 32px | Layout gaps (main column ↔ sidebar) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (drop zone vertical centering) |

Exceptions: icon-only touch targets (file-picker button, remove-document button) are a minimum **44×44px** hit area even when the visible icon is 16–20px — WCAG 2.5.8 target size; justify: keyboard/trackpad demo before judges, no mobile breakpoint required this phase.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label (meta, badges, page chips, buttons) | 13px | 600 | 1.4 |
| Heading (section headings, chunk-count header) | 20px | 600 | 1.2 |
| Display (page title) | 28px | 600 | 1.2 |

Exactly two weights: **400 (regular) + 600 (semibold)**. Verbatim chunk text renders at 16px/400/1.5 in the body font — never truncated with ellipsis (verbatim fidelity is the product's core value; wrap instead).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Upload agreement"** (verb + noun — never "Submit" or bare "Upload") |
| Empty state heading | "No document yet" |
| Empty state body | "Drop a PDF or TXT file here, or choose one from your computer. Files never leave this machine." |
| Privacy reassurance (near drop zone, verbatim) | "Processed entirely on this machine. No document content is sent over the network." |
| Loading state (upload in-flight) | "Extracting pages → chunking → embedding locally. This can take a moment on CPU." (with spinner; CTA disabled and relabelled "Processing…") |
| Error: unsupported type | "That file is a {ext} file. Try a PDF or plain-text (.txt) document." |
| Error: too large / too many pages | "That file is {size} / {pages} pages. Try a document under 20 MB and about 300 pages." |
| Error: server/Ollama failure | "Processing failed on the local model. Check that Ollama is running (ollama serve), then upload again." |
| Success header | "{filename} — {N} chunks" (pluralise: "1 chunk" singular) |
| Destructive confirmation | Remove document → confirm dialog: "Remove {filename}? Its extracted chunks will be deleted from this session. This cannot be undone." Buttons: "Remove document" (destructive red) / "Keep document" (neutral). |
| No-chunks edge case | "No text chunks were extracted. The file may be scanned images — try a text-based PDF or a .txt file." |

## UI Considerations

Applicable state considerations resolved: 9 covered, 0 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | list-collection | ✅ covered | Zero chunks → drop zone + "No document yet" empty-state copy from the Copywriting Contract |
| empty | form | ✅ covered | No file chosen → CTA "Upload agreement" rendered disabled until a file is selected |
| loading | form | ✅ covered | Upload in-flight → CTA disabled + relabelled "Processing…" + spinner + the verbatim loading copy; no skeleton needed (single POST, no streaming this phase) |
| loading | list-collection | ✅ covered | Chunk list renders only after upload completes; previous list stays visible with a top progress bar if a second document replaces it |
| error | form | ✅ covered | Each failure mode (unsupported / oversized / model failure) renders a destructive-red banner above the drop zone with problem + next action verbatim; never a crash (01-CONTEXT discretion: reject >20 MB or >~300 pages with a clear message) |
| error | list-collection | ✅ covered | Upload replacing a document that then fails → old chunk list preserved, error banner shown, no data loss |
| populated | list-collection | ✅ covered | Header "{filename} — {N} chunks"; each row = page chip (e.g. "p. 3") + full verbatim chunk text on a white card |
| partial | form | ✅ covered | File selected but not submitted → CTA enabled, filename shown next to the chooser; Remove-document button hidden until a document exists |
| overflow | list-collection | ✅ covered | Chunk list scrolls inside the main column (`max-height: calc(100vh - header)`, `overflow-y: auto`); header + drop zone stay fixed; no horizontal scroll at ≥1024px |
| zero-one-many | list-collection | ✅ covered | "1 chunk" vs "N chunks" singular/plural in the header; one row and many rows use identical card spacing (md) |
| long-text | static-content | ✅ covered | Chunk text wraps fully (no ellipsis, no clamp) — verbatim quotes must be judge-readable; page chip stays left-aligned and does not reflow |
